# Roadmap

## Now

A quality strategy is a set of steps, each a skill of its own: the project's context, each
stakeholder's view, priorities for a release, the written strategy, and then one priority at a
time. The pack runs as a plugin in Claude Code and in Codex.

Earlier versions have been used by the authors and a few other people. This version is new, and
one of the authors has taken a project of her own through it. The
[known issues](KNOWN-ISSUES.md) list what we know can go wrong.

## Next

- **Fix the smaller known issues,** in 0.5.x releases.
- **A default strategy to start from.** The pack will begin from a ready-made strategy for a
  typical software project, so that it can suggest useful work before you have answered
  everything. What it reads in your project and what you tell it then correct that starting
  point, and it will stay visible which parts are still assumptions.

## Later

The larger known issues need design work, and real use will guide it. We expect that to include
shorter conversations, a last step that rewrites the strategy shorter, projects with many
stakeholders and priorities, and support for products whose results vary from run to run, such as
AI features. The [open questions](OPEN-QUESTIONS.md) say what we are unsure about, and your
experience would help answer them.
