# Prioritise release quality: re-ordering later

The user can change the order of the release's priorities at any point, from `priority-deepdive`,
`quality-strategy` or this skill. A re-order needs only the steps below, not the whole skill,
because the order is kept in the priorities' own record.

1. Unless you have already done so in this session, find the quality folder, run `status` and read
   the progress note, as step 1 of [the skill](../SKILL.md#1-choose-the-release-and-check-every-view-is-in)
   says, because the note may hold a question, waiting for their return, that the new order would
   depend on.
2. Take the new order in their words.
3. Where it changes a rating, work out the ratings from it and show them once as your reading, for
   them to correct, as [reading the ratings](the-table.md#read-the-ratings-from-their-order) says.
4. Re-sort the table, and note beside it that this order is a re-order, because the write-up then
   keeps the sections in this order. The earlier order, with its date, and any rating they changed
   go in the [decision log](../../../references/templates/every-document.md#what-is-true-now).
5. If the strategy has been written up, do all of this in the same save, because a worker may take
   any part of it away and act on it: move its sections into the new order; read the sections and
   the opening for anything that depends on the old order, such as a next action that waits on a
   priority now placed after it, and correct it; and bring the bottom line up to date.
6. Record no step for a re-order, because recording the priorities step would say the whole step
   was done again.
