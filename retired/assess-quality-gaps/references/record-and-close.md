# Assess quality gaps: record and close

This is how the assessment is recorded and the session closed, once the user has answered the
findings or a stop came first.

1. In a strategy, write the strategy's part on where things stand, as [writing your
   part](../../../references/writing-your-part.md#writing-your-part-at-a-steps-close) says, once
   the user has answered the findings, when the strategy has no such part yet. An existing part has
   been kept up to date finding by finding, as [while investigating](while-investigating.md#as-each-finding-is-made)
   says; bring it up to date with their answer.
   - It says how good each priority is now, and the pattern. In the pattern, say what would settle
     each cluster of unknowns, and leave work and its order to the plan of work.
   - The questions the findings leave open go to the Open notes as they are, each with how it
     could be found out, as [the Open guidance](../../../references/open-section.md) says. The
     strategy's part on open questions is written from them, as [writing the
     strategy](../../../references/writing-the-strategy.md) describes, and names nobody to ask.
   - Bring the strategy's opening up to date, with the bottom line as their answer settled it, and
     its open questions too.
2. In a strategy, record where the assessment stands. Run on its own with no strategy, this skill
   records nothing, because there is no strategy to record it in.
   - `step assessment done` when [done-when](../SKILL.md#done-when) holds. Some rows' checks wait on
     someone else, on the release being in people's hands, on work the plan of work will schedule,
     or on a check the user chose to leave. Each such row is a finding, not a reason to keep the
     step open, because the plan of work is where missing evidence gets scheduled. It is judged
     again when its evidence arrives, and the step recorded as revised, as [where the strategy
     stands](../../../references/where-things-stand.md) says.
   - `step assessment started`, with a note saying what it waits on, when this pass was cut short.
     That means findings the user has not yet seen, a check the agent could run but a stop came
     first, or one the user has taken on as part of this pass ("I'll run that and tell you").
     Waiting on someone else is not that. Tell the user.
3. In a strategy, run `status`. After `started` it also offers going on to the plan of work from
   what is known, or connecting the strategy as it stands: offer those too.
4. Lay out no work in the closing message, because the plan of work does that. To write it, open
   [stopping and coming back](../../../references/stopping-and-returning.md) now, and update the
   progress note as it says too.
5. In a strategy, unless they have just said what to do next, wait for their answer to the offer
   that message ends with, because no step starts before the user chose it.
