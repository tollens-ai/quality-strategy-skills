# Plan quality work: save and close

## If they stop before replying to the plan

When they stop during the questions, or before they have replied to the plan, the step is not done,
and what is saved must not read as agreed:

- A proposal already shown to them is saved as proposed, not agreed, because a piece they did not
  answer stays proposed. Do step 1 below before that first save.
- Nothing is saved as the plan, and `step plan done` is not recorded, because the plan is theirs
  only once they have replied.
- Then go on from step 6. The progress note names the question still owed, so that the next session
  starts from it.

## Once they have replied

1. Before the first save, open [where the documents
   live](../../../references/document-home.md#before-the-first-save) and do what it says, because the
   user has to know who can read what is about to be saved.
2. Save the plan. In a strategy, it goes in the plan notes, as [the plan
   notes](../../../references/saving-records.md#the-plan-notes) describe, or in the planning
   document the user gave. Outside a strategy, it goes in the document the user names or in a
   finding on its own, as [a result outside a
   strategy](../../../references/writing-your-part.md#a-result-outside-a-strategy) describes. A
   clearer question is saved in the Open section, marked as still open.
3. Record in the Open section any decision to delay or leave out work, and any risk the user
   accepted. Delay does not make a priority less important, and a known issue or a disagreement
   between stakeholders can stay unresolved.
4. In a strategy, open [writing the strategy](../../../references/writing-the-strategy.md) and do as it
   describes: write the strategy's plan of work, and bring the strategy's opening and open
   questions up to date.
5. In a strategy, once the user has answered, record `step plan done`, adding a note that it ended
   with a question when it did. Run on its own with no strategy, this skill records nothing,
   because there is no strategy to record it in.
6. In a strategy, run `status`.
7. Open [stopping and coming back](../../../references/stopping-and-returning.md) now, then update
   the progress note and write the closing message as it says.
8. In a strategy, unless they have just said what to do next, wait for their answer to the offer
   that message ends with, because no step starts before the user chose it.
