# Plan the measurement: where to start

Opened from [the skill](../SKILL.md) at the start, before the discussion, because these steps find
the saved work and settle which rows this plan covers and what each is judged against.

1. Find the quality folder and any saved work, as [where the documents
   live](../../../references/document-home.md) describes.
2. If there is no strategy, the request is one quality question on its own, and the earlier steps
   need not have run. [Where the strategy stands](../../../references/where-things-stand.md) says how
   to tell. Do these in place of the rest of this section, asking only for what the request did not
   say:
   1. Say what this step offers: agreeing how to find out how good something is, before any
      measuring.
   2. Ask what question is to be judged, and whose view it is, in the user's words.
   3. Ask how good it must be. If they don't know, record the bar as unknown with what would
      settle it, and plan the row all the same, because they settle a bar better with evidence.
   4. Plan that one row as the rest of this skill describes.
3. In a strategy, run `status`, as that reference describes. Read the priorities table, in the
   priorities notes or, in an older strategy without them, as [the records
   guide](../../../references/quality-model.md#records) says. If the priorities are not done, or
   someone is still to be heard from, say so.
4. Say which rows this plan covers. A request about one quality question can stay about that one.
   In a strategy, a row is in scope for what it carries, whatever its rating or lack of one, because
   a row left unrated or rated Low can still hold what stops the release. The records settle these
   now:
   - the rows the release waits for;
   - every High and Medium row;
   - any row the user has named, including an unrated row whose Open entry says, as its way of
     finding out, that they want it looked into before they rate it.

   Two more come in once what is known has been gathered, in [making the
   plan](making-the-plan-and-saving.md), because a fresh session has not yet read the records that
   hold them:
   - any row with a known fault in any record: the pre-read, the interview, the context, a profile
     or an earlier assessment;
   - any row where nobody knows where things stand and a bad answer would hurt someone.

   The rows with none of these are named in one line, together, with their ratings and their open
   questions. An unrated row is never kept out where a Low row would come in.

   Name each row's view and bar only when the row comes up, because the user agreed them in the
   priorities. The bar is how good it must be for the release or, where that is still open, each
   stakeholder's goal named in the row.
5. If time has passed or something has happened since the priorities were set, ask what has
   changed. A fresh session on the same day is not a change.
6. Mark anything that is a draft or unknown, and say any assumption known to be out of date.
7. If a row has neither a release bar nor a stakeholder's goal, clarify it only as far as this plan
   needs. If that does not give it a bar, record the bar as unknown with what would settle it, and
   plan the row like any other: no check is judged against a bar nobody set.
