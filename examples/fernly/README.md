# Fernly — a complete worked sample

Fernly is a **fictional** plant-care app (iOS/Android/web; reminders, photo plant-ID, household sharing, Bluetooth soil sensors) with a complete, realistic quality doc-set, shipped so you can see what the skills produce — and try the post-processing skills in two minutes without doing the interview first.

```
quality/strategy.md          the full quality strategy (7 parts + TL;DR + triage rubric)
quality/test-strategy.md     the engineering companion (learning needs, order, human/agent split)
quality/artefacts/           three artefacts generated by /quality-artefacts from freeform asks:
  quality-snapshot-card.svg    "a tweetable one-image summary"               (1200×675 SVG)
  quality-story.html           "tell our quality story"                      (multi-frame offline HTML)
  the-two-holes.svg            "the overview as one poster"                  (1080×1350 SVG)
```

Each artefact was a separate run with a different audience and message — that's the point: the skill **designs** a view per request, it doesn't fill a template. The story is six full-screen frames, each one a self-contained poster you can screenshot on its own. Open the HTML straight from disk; it makes no network requests.

## ⚠️ One project's answers, not a starting point

Everything in `quality/` follows from facts that are deliberately *not your facts* — a two-person studio, a March photo-loss incident, a 4.2-star rating slide, a September paid relaunch, one specific BLE probe. **Your stakeholders, dimensions, bars, and non-goals will differ**, and the dangerous failure mode is subtle: a copied strategy looks complete while pointing your effort at someone else's risks. Run `/quality-strategy` and answer the interview for your own project; use Fernly only to calibrate what *finished* looks like.

For the same reason, **no skill in this pack reads this sample while it runs.** Keeping it out of every prompt path is a deliberate guard, not an oversight — agents anchor hard on whatever strategy document is in front of them, and a sample in context would quietly become a template. Contributors: don't add references to `examples/` from any `SKILL.md` or step file.

One more maintenance rule: **the sample's fictional evidence must be the kind its fictional team could actually possess** — convenient evidence is a verisimilitude bug. (We shipped one: a quantified exit-survey churn stat in a product whose whole premise is that churn causes are invisible; fixed 2026-06-11. A two-person studio with zero instrumentation has App Store reviews, a support inbox, and anecdotes — not survey percentages.)

## Second role: the standard regression fixture

Fernly is also the pack's fixture for exercising the *downstream* skills (the ones that consume a finished strategy) without a live interview. When changing `/quality-artefacts`, `/strategy-variants`, `/operational-distillation`, the review skills, or anything else that reads `quality/strategy.md`, smoke-test against a scratch copy of this directory:

1. **Runs end-to-end** — the skill completes against the sample without asking questions it shouldn't need.
2. **Leak-grep** — outputs contain no process narration (grep for `turn-`, `subagent`, `scratch`, `dispatch`, `sealed`).
3. **Review-skill pass** — where a review skill exists for the produced artifact type, it passes (or its findings are understood).

Work on a copy outside the repo so the committed sample stays pristine; if a skill change legitimately requires the sample itself to change, that's a signal to look hard at the change.
